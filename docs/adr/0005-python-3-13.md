# Python 3.13 via pyenv

## Context
mlx, mlx-whisper and pyobjc (used by ocrmac) ship binary wheels for macOS arm64 only for a range of Python versions. The system Python 3.9 is too old, and uv's own managed Python downloads would bypass the owner's pyenv setup.

## Decision
Pin Python 3.13 (the newest version with wheels for all three) with pyenv (`.python-version`), constrain `requires-python = ">=3.13,<3.14"`, and tell uv to use only system interpreters and never download one. The venv's python is a symlink into pyenv's 3.13 build, so launchd needs no pyenv shims.

## Consequences
- Upgrading Python waits on mlx and pyobjc wheels.
- Removing the pinned pyenv version breaks the venv; recreate it with `uv venv --python "$(pyenv which python)" && uv sync`.
